Hermes Project B.O.S.S. — Asana Agent Build Instructions
What Asana is and how it works
Asana is a work management platform organized around a work graph: interconnected objects including tasks, projects, portfolios, goals, and users. Everything you build lives inside this graph and can be referenced, linked, and automated.

Core object hierarchy:

	•	Workspace/Organization — the top-level container
	•	Projects — collections of tasks, organized into sections
	•	Tasks — the atomic unit of work; can have subtasks, custom fields, assignees, due dates, dependencies, and comments
	•	Portfolios — track multiple projects in one view
	•	Goals — strategic objectives linked to projects and portfolios
	•	Rules — if/then automations that trigger on field changes, task events, etc.

How to authenticate
All API calls require a Personal Access Token (PAT) or OAuth2 token.

Authorization: Bearer {YOUR_PERSONAL_ACCESS_TOKEN}
Content-Type: application/json
Base URL: [https://app.asana.com/api/1.0 !UNVERIFIED!](https://app.asana.com/api/1.0)
Get your PAT from: Asana → Profile Settings → Apps → Developer Apps → Personal Access Token.

STEP 9 — Session log protocol
Every time a task is completed (detected via webhook), your agent should immediately create a subtask using this template:

POST /tasks
{
  "data": {
    "name": "Session Log — [Agent Name] — [Task Name] — [Date]",
    "parent": "{completed_task_gid}",
    "memberships": [{"project": "{project_gid}", "section": "{session_logs_section_gid}"}],
    "notes": "## Session Log\n\n### What I did\n\n### What I learned\n\n### What surprised me\n\n### What I would do differently\n\n### Trust delta\n\n### Memory promotion candidates\n\n### Open questions"
  }
}

Key rules agents must follow
	1.	Never skip a gate. Check dependency status before marking any task complete.
	2.	Always post a session log on task completion — no exceptions.
	3.	Never promote a claim marked Unsupported — hard block.
	4.	Any capital-risk action must create an approval task and wait for approval_status: approved before proceeding.
	5.	Agent Trust Score below 0.35 = L0 only. No trade drafts, no promotions.
	6.	All comments are append-only. Never edit a prior comment — post a new one.
	7.	Store all GIDs returned from POST calls — you'll need them for linking, dependencies, and updates.

Webhooks — full setup
Asana webhooks require a handshake on first connection. When Asana sends the initial POST to your endpoint, it includes an X-Hook-Secret header. Your endpoint must echo it back immediately:

# Handshake handler (FastAPI example)
@app.post("/asana-webhook")
async def webhook(request: Request):
    secret = request.headers.get("X-Hook-Secret")
    if secret:
        return Response(headers={"X-Hook-Secret": secret})
    
    payload = await request.json()
    await handle_events(payload["events"])
    return {"ok": True}
Webhook best practices:

	•	Respond in under 10 seconds or Asana will retry
	•	Use a queue (Redis, SQS, etc.) — receive fast, process async
	•	Asana will deactivate webhooks after repeated failures — build a health check that re-registers if inactive
	•	Verify the X-Hook-Signature header on every event for security

Re-register webhook if deactivated:

GET /webhooks?workspace={workspace_gid}
# Check "active": false → re-POST to /webhooks

Pagination — critical for large datasets
All list endpoints are paginated. Always handle next_page:

def get_all(endpoint, params):
    results = []
    params["limit"] = 100
    while True:
        r = requests.get(endpoint, params=params, headers=headers)
        data = r.json()
        results.extend(data["data"])
        if not data.get("next_page"):
            break
        params["offset"] = data["next_page"]["offset"]
    return results

Rate limits — avoid getting blocked
	•	Asana enforces ~150 requests/minute per token
	•	On 429 Too Many Requests, respect the Retry-After header
	•	Use exponential backoff:
import time

def api_call_with_backoff(fn, retries=5):
    for i in range(retries):
        r = fn()
        if r.status_code == 429:
            time.sleep(2 ** i)
            continue
        return r
    raise Exception("Rate limit exceeded after retries")

Batch operations
For bulk task creation (e.g. spinning up all Phase 0 tasks at once), use the batch API to reduce round trips:

POST /batch
{
  "data": {
    "actions": [
      {"method": "post", "relative_path": "/tasks", "data": {...}},
      {"method": "post", "relative_path": "/tasks", "data": {...}}
    ]
  }
}
Max 10 actions per batch request.

Dashboard — what agents should know
Asana dashboards live inside portfolios and are built from saved report charts. Agents cannot create dashboard charts via API — this is UI-only. However, agents can maximize dashboard usefulness by:

1. Keeping custom fields clean and consistent
Charts are only as good as the data. Agents must always set Gate Status, Risk Level, SOSOG Confidence, and Signal Family on every task — never leave them blank.

2. Recommended chart types to build manually:
Panel	Chart type	Field to track
Gate funnel	Bar chart	Gate Status
Agent trust scoreboard	Number chart	Agent Trust Score
Signal family health	Pie chart	Signal Family
Autonomy ladder	Bar chart	Autonomy Level
Approval queue	Task list	Review Required = Yes
Session log activity	Number chart	Tasks in Session Logs section
Source freshness failures	Task list	Gate Status = Hard Fail
3. For real-time agent monitoring outside Asana, pipe Asana webhook events into Grafana via a simple bridge — this gives you the live Prometheus-style dashboards the build spec calls for, while Asana remains the governance and task layer.

Subtask depth — important constraint
Asana supports subtasks, but only one level of subtasks is reliably visible in project views. For the session log system:

	•	Keep session logs as subtasks of their parent task 
	•	￼
	•	Also add them to the Session Logs section via memberships so they're visible in the main project view 
	•	￼
	•	Don't go deeper than 2 levels or they'll disappear from dashboards

Enum option GIDs — cache them
When you create custom fields, the API returns enum option GIDs. Cache these immediately — you'll need them every time you set a field value on a task. Losing them means extra API calls to look them up.

Error handling — what agents must catch
Error	Meaning	Action
403 Forbidden	Missing permissions or wrong workspace	Check token scope and workspace GID
404 Not Found	GID is wrong or object deleted	Re-fetch GID, log and skip
412 Precondition Failed	Stale data / optimistic lock	Re-fetch and retry
429 Too Many Requests	Rate limited	Exponential backoff
500 / 503	Asana server error	Retry with backoff; alert if persistent
